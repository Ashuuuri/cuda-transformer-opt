A Study of CUDA Optimizations in Transformer Layers

Heling Huang  ·  Shengjing Zhang  ·  Jonathan Chen

Cornell University  ·  CS 5220: Applications of Parallel Computers  ·  NVIDIA A100 (Perlmutter / NERSC)

INTRODUCTION

Transformer models power modern AI—but their two core operations, attention and the feed-forward (MLP) layer, are often slower than they should be. On the A100 GPU, these kernels are bottlenecked by memory bandwidth, not compute.

The GPU spends more time moving data than doing math. Closing this gap requires rethinking how data is laid out and how precision is used.

We explore two complementary strategies:

  • Algorithmic optimization — redesign kernels to reduce data movement (fused attention, tiled GEMM with Tensor Cores)
  • Precision reduction — compress 16-bit floats to 8-bit integers (INT8), halving memory traffic and doubling theoretical throughput

Our central question

We first push FP16 performance as far as possible. Then we ask: can INT8 quantization go further? And if not immediately — why not?

METHODOLOGY

Custom CUDA kernels for attention and MLP, evaluated on an A100 (sm_80) across sequence lengths 512–4096 and model sizes 512–2048. The first four strategies form our optimized FP16 baseline; INT8 quantization is then layered on top.

  • Kernel Fusion — The full attention pass (QKᵀ→softmax→Attn×V) is fused into a single kernel via online softmax and K/V tiling, so the N×N score matrix never materializes in HBM. GELU is fused into the MLP GEMM₁ epilogue.
  • WMMA Tensor Cores — MLP GEMMs use FP16 WMMA with 64×64 block tiles, sustaining near-peak throughput on A100's 312 TFLOPS FP16 units.
  • cp.async Double Buffering — Asynchronous tile loads are overlapped with Tensor Core computation, hiding HBM latency and keeping compute units continuously fed.
  • Shared Memory Swizzling — Shared memory addresses are permuted to eliminate bank conflicts on tile loads, maximizing smem bandwidth.
  • INT8 Quantization — Per-tensor symmetric INT8 is applied to both layers, built on the same tiling structure as the FP16 kernels. Naïve INT8 was slower — pipeline overhead (host syncs, extra kernel launches, premature dequantization) outweighed the 2× throughput advantage. We removed each bottleneck systematically.

CONCLUSIONS

Algorithmic optimization works

  • Fused attention with online softmax eliminates O(N²) HBM traffic — a single kernel handles QKᵀ, softmax, and Attn×V without materializing the score matrix.
  • WMMA MLP with 64×64 tiling and cp.async double buffering keeps Tensor Cores continuously fed, approaching hardware peak throughput.
  • Shared memory swizzling removes bank conflicts, maximizing smem bandwidth across both sub-layers.

INT8 is not a free lunch

  • Naïve INT8 substitution is slower than optimized FP16 — pipeline overheads dominate the 2× throughput advantage.
  • The culprits: host–device sync on scale values, an extra requantization kernel between GEMMs, and premature dequantization in shared memory.

Co-design is the key

  • INT8 halves the shared memory footprint — but only if values stay INT8 inside the kernel. Dequantizing early to FP16 wastes that space and kills occupancy.
  • The dtype is the easy part. Rethinking smem layout, tiling, and epilogues around INT8 is where the actual speedup comes from.
Realizing INT8's advantages requires co-designing quantization with the memory layout. Changing the dtype is the easy part — making smem, tiling, and epilogues INT8-aware is where the gains come from.
FUTURE WORK
  • Quantize softmax attention weights to enable INT8 WMMA for the attn×V step, completing the full INT8 attention pipeline
  • Increase INT8 MLP block tile size — freed smem budget allows 128×128 tiles vs. current 64×64
  • Add cp.async prefetch to INT8 kernels to overlap compute and memory load
  • Fuse INT8 attention and MLP into a single transformer block, amortizing quantization cost across layers
